# Data Directory

Raw audio is **not** committed to this repository (see root `.gitignore`) because CREMA-D is several GB. Follow these steps locally:

## 1. Download CREMA-D

Via Kaggle:
```bash
# requires a Kaggle account + kaggle.json API token (do NOT commit kaggle.json)
kaggle datasets download -d ejlok1/cremad
unzip cremad.zip -d data/raw/
```
or via `kagglehub` in Python:
```python
import kagglehub
path = kagglehub.dataset_download("ejlok1/cremad")
```

After extraction you should have:
```
data/raw/AudioWAV/*.wav
```

## 2. Folder contents

| Folder | Committed? | Contents |
|---|---|---|
| `raw/` | ❌ No | Original CREMA-D `.wav` files |
| `processed/` | ❌ No | Extracted MFCC (and optionally delta/delta-delta or log-mel) feature arrays, generated by `src/features/extract_features.py` |
| `splits/` | ✅ Yes | CSV files listing which **actor IDs** (not clip filenames) belong to train/val/test — small, text-based, and important for reproducibility |

## 3. Why actor-level splits?

CREMA-D has multiple clips per actor. A random clip-level split can put the same actor's voice in both train and test, letting a model learn speaker identity rather than emotion — this inflates test accuracy and would be flagged as a data leakage issue under the rubric's Data Preprocessing criterion. `src/data/split.py` splits by **actor ID** so no actor appears in more than one of train/val/test.

## 4. Regenerating features

```bash
python -m src.features.extract_features --config configs/preprocessing.yaml
```
This reads `data/raw/AudioWAV/`, applies the split defined in `data/splits/`, and writes feature arrays to `data/processed/`.
